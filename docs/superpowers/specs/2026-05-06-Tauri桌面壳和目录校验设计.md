# Tauri 桌面壳和目录校验设计

日期：2026-05-06

## 背景

当前 `feature/front-prototype` 已完成 Vue 前端原型、运行时接口、`mockRuntime`、最小 `tauriRuntime` 和设置页运行环境展示。README 中的下一步是“接入 Tauri 后端目录校验命令”。

实际代码结构中还没有 `src-tauri/`，也没有 `@tauri-apps/api` 依赖。因此下一阶段不能只改 `tauriBridge.ts`，需要先建立最小 Tauri 桌面壳，再把目录校验能力从前端模拟提示替换为真实桌面命令调用。

本阶段目标是做最小桌面能力闭环：应用能在浏览器环境继续使用 mock，在 Tauri 环境中通过后端命令检查产出资源目录是否存在、是否为目录、是否可写。

## 目标

- 新增最小 `src-tauri/` 工程结构。
- 新增 Rust 命令 `check_directory(path)`。
- 前端 `tauriBridge` 在 Tauri 环境中调用后端命令。
- 浏览器环境仍不加载或依赖桌面能力，现有 mock 演示保持可用。
- 设置页“运行环境”重新检测能拿到真实目录校验结果。
- 补齐前端 bridge 测试和 Rust 命令的可测试边界。
- README 记录桌面壳能力、验证方式和本机可能的 native 构建限制。

## 非目标

- 不接真实 Agent API。
- 不解析真实 docx。
- 不生成真实 zip。
- 不做文件选择器。
- 不打开系统目录。
- 不引入 SQLite 或后端持久化。
- 不重做前端页面布局。

这些能力属于后续真实桌面能力阶段。本阶段只接目录校验命令。

## Rust 命令设计

命令签名：

```rust
#[tauri::command]
fn check_directory(path: String) -> DirectoryCheckResult
```

返回结构：

```rust
#[derive(serde::Serialize)]
struct DirectoryCheckResult {
    exists: bool,
    writable: bool,
    message: Option<String>,
}
```

校验规则：

- 路径为空：`exists = false`，`writable = false`，message 为 `请先配置产出资源目录。`
- 路径不存在：`exists = false`，`writable = false`，message 为 `产出资源目录不存在。`
- 路径存在但不是目录：`exists = false`，`writable = false`，message 为 `产出资源路径不是目录。`
- 路径是目录但不可写：`exists = true`，`writable = false`，message 为 `产出资源目录不可写。`
- 路径是目录且可写：`exists = true`，`writable = true`，message 为空。

可写性判断使用一个临时探针文件：

- 文件名固定前缀 `.fr_write_probe_`，追加时间戳或进程内随机后缀。
- 尝试写入少量字节。
- 写入成功后立即删除。
- 删除失败不影响 `writable = true`，但 message 可保留清理提示。

## 前端 Bridge 设计

`src/runtime/tauriBridge.ts` 继续是唯一访问 Tauri API 的前端文件。

实现规则：

- `isAvailable()` 仍以 `window.__TAURI_INTERNALS__` 做轻量检测。
- `checkDirectory(path)` 在 Tauri 环境中动态导入 `@tauri-apps/api/core`。
- 调用 `invoke<DirectoryCheckResult>('check_directory', { path })`。
- 如果导入或调用失败，返回：

```ts
{
  exists: false,
  writable: false,
  message: '桌面目录校验命令调用失败。'
}
```

动态导入可以避免浏览器测试直接加载桌面 API。测试中通过注入 `invoke` 函数验证 bridge，不依赖真实 Tauri 进程。

## 运行时行为

现有运行时选择不变：

- 浏览器环境：`createDefaultRuntime()` 返回 `mockRuntime`。
- Tauri 环境：`createDefaultRuntime()` 返回 `tauriRuntime`。

变化点是：`tauriRuntime.validateEnvironment(settings)` 会通过 `tauriBridge.checkDirectory()` 获取真实目录状态，而不是固定返回“命令尚未接入”。

浏览器模式仍不阻塞 mock 演示。

## 测试策略

前端测试：

- `tauriBridge` 在无 Tauri API 时返回不可用。
- `tauriBridge` 能通过注入 invoke 返回目录校验结果。
- `tauriBridge` 在 invoke 失败时返回可恢复错误消息。
- 现有 `tauriRuntime`、Store、Settings 测试继续通过。

Rust 测试：

- 抽出纯函数 `check_directory_path(path: &Path) -> DirectoryCheckResult`。
- 测试不存在路径。
- 测试文件路径不是目录。
- 测试可写临时目录。

最终验证：

```bash
npm run test
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
```

如果当前 Windows 环境缺少 Rust/MSVC 链接工具，`cargo test` 的失败应记录为环境阻塞，但前端测试和构建必须通过。
